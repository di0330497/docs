Helm이 해결하는 문제와 패키지 관리자 개념

Helm은 쿠버네티스용 패키지 관리자로, 여러 매니페스트를 차트 하나로 묶어 설치와 공유와 재사용을 쉽게 한다.

#1문제 상황

쿠버네티스에 앱을 올리려면 Deployment와 Service, ConfigMap 같은 매니페스트를 여러 개 직접 작성하고 관리해야 했다. 환경이 개발과 스테이징, 운영으로 나뉘면 같은 내용을 복사해서 고치는 일이 반복됐다. 손으로 고치다 보면 버전마다 설정이 어긋나고 배포할 때마다 같은 실수가 되풀이됐다.

#2핵심 질문

서로 얽힌 쿠버네티스 매니페스트 묶음을 하나의 단위로 묶어 설치하고 공유할 수는 없을까?

#3동작 예시

워드프레스 배포에 필요한 웹 서버와 데이터베이스 설정을 Helm 차트 하나로 묶어 두면, 사용자는 차트 이름만 지정해 설치하고 같은 차트를 다른 값으로 개발 환경과 운영 환경에 각각 배포한다.

#4동작 과정

  1. 묶기연관된 매니페스트를 차트라는 패키지 단위로 모으고 버전을 붙인다.
  2. 배포하기차트를 클러스터에 설치하면 Helm이 매니페스트를 생성해 쿠버네티스에 전달한다.
  3. 공유하기버전이 붙은 차트를 저장소에 올려 다른 팀도 같은 내용으로 설치하게 한다.

  3. 릴리스 생성차트와 값을 합쳐 설치하면 클러스터에 릴리스라는 실행 단위가 생긴다.

  3. 호환 유지v2 차트는 그대로 동작하게 하고 차트 v3는 실험 플래그 뒤에서 시험한다.

Helm 설치와 바이너리 검증

Helm은 공식 바이너리나 스크립트 또는 OS 패키지 관리자로 설치하며, 배포 전 SHA256과 GPG 서명으로 진위를 확인한다.

#1문제 상황

실행 파일을 어디서 받아 설치해야 하는지 방법이 흩어져 있었고, 내려받은 파일이 변조됐는지 확인하는 절차가 생략되기 쉬웠다. 소스 빌드와 패키지 관리자 설치가 섞이면서 기준이 불분명해졌다.

#2핵심 질문

공식 경로로 Helm을 설치하고 받은 파일이 정품임을 어떻게 확인해야 할까?

#3동작 예시

릴리스 페이지에서 운영체제용 압축을 받아 풀고 helm 바이너리를 경로에 옮긴 뒤, SHA256 체크섬과 maintainer 공개키 기반 GPG 서명을 검증하고 helm version으로 동작을 확인한다.

#4동작 과정

with 블록 안에 들어가면 바깥의 Release 이름이 안 보여 렌더가 실패했다. 같은 값을 여러 번 계산하면서 템플릿이 길어지고 실수가 늘었다.

#3동작 예시

#4동작 과정

  1. 담아 두기:= 연산자로 이름 붙은 변수에 값을 저장한다.
  2. 범위 넘나들기$ 변수는 with와 range 안에서도 그대로 보인다.
