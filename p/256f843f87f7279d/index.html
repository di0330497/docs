1Rancher 개요와 구조01-01

Rancher Manager란 무엇인가

여러 쿠버네티스 클러스터를 한 화면에서 만들고 관리하는 SUSE의 컨테이너 관리 플랫폼이다

#1문제 상황

클러스터마다 따로 kubectl로 접속하고 계정과 권한을 따로 관리했다. 클러스터가 늘면 접속 정보가 흩어지고 같은 사람을 매번 등록해야 했다.

#2핵심 질문

여러 클러스터의 인증과 권한과 관찰을 한곳에서 다룰 수는 없을까?

#3동작 예시

EKS 클러스터와 직접 만든 RKE2 클러스터를 Rancher에 붙이면 두 클러스터의 사용자를 한 화면에서 관리한다. 외부 CI/CD가 없어도 Fleet이 깃에서 워크로드를 자동으로 올린다.

#4동작 과정

  1. 클러스터 모으기호스티드에서 만들거나 노드에 직접 깔거나 기존 클러스터를 가져온다. 관리 대상이 한 화면에 모인다.
  2. 한곳에서 통제하기인증 프록시와 RBAC(역할 기반 접근 제어, 누가 무엇을 할 수 있는지 정하는 틀)로 접근을 통제한다. 모니터링과 알림과 로그 연계가 붙는다.
  3. 앱 올리기Helm(쿠버네티스 패키지 묶음 도구) 앱 카탈로그와 Fleet(깃 기반 지속 배포)으로 워크로드를 배포한다.

관리 클러스터와 다운스트림 클러스터

Rancher 자체가 뜨는 관리 클러스터와 Rancher가 관리 대상으로 삼는 다운스트림 클러스터를 구분하는 개념이다

#1문제 상황

각 클러스터 API에 직접 인증 정보를 들고 접속했다. 클러스터마다 계정이 달라 누가 무엇을 했는지 한눈에 안 보였다.

#2핵심 질문
