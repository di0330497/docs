1상대의 출발점 확인

많은 입문 프로그래밍 과목은 Python 문법(if, for, while, 변수 선언 등)부터 시작한다.
CS106A는 이런 문법 자체보다 "어떻게 문제를 읽고,
그 문제를 함수로 쪼개고,
읽기 좋은 코드로 푸는가"라는 방법론을 먼저 가르친다.
프로그래밍 경험이 없어도 문제 해결의 사고 과정과 코드 구조를 배울 수 있다는 뜻이다.

2질문 제기

CS106A는 Python 문법이 없어도 배울 수 있는가?

3구조적 핵심 예시

사다리꼴 모양으로 벽돌을 쌓는 과제를 받았다고 하자.
미숙한 사람은 move → turn_left → move → turn_left 를 몇 십 번 반복 복사하지만,
CS106A 학생은 벽을 그리는 함수,
높이를 늘리는 함수로 쪼개서 각각을 간단하게 쓰고 조합한다.
같은 언어와 문법으로 작동하지만,
사고 방식과 결과 코드의 질이 완전히 다르다.

4단계별 동작 과정

  1. 문제를 함수로 쪼개기큰 문제를 작은 함수들로 나눈다. 사다리꼴은 "1층 쌓기" 함수와 "층 높이 늘리기" 함수로 본다.
  2. 각 함수를 깔끔하게 설계하기반복되지 않으면서도 의도가 명확한 작은 함수를 만든다.
  3. 함수들을 조합해 전체 프로그램 완성하기쌓은 함수들을 조합해 전체 프로그램을 만들면, 코드를 읽는 사람이 의도를 한눈에 알 수 있다.

많은 사람들이 "파이썬 프로그램을 실행한다"는 표현을 쓰지만,
그 안에서 정확히 무엇이 일어나는지 모른다.
사실 Python 프로그램은 단지 텍스트 파일이다.
.py 파일이 마법처럼 작동하는 게 아니라,
그 파일을 읽어주고 한 줄 한 줄 실행해 주는 프로그램(Python 인터프리터)이 있어야 한다.

2질문 제기

.py 파일이 어떻게 실제로 움직이는 명령이 되는가?

3구조적 핵심 예시

karel.py를 더블클릭해도 아무것도 안 된다.
하지만 명령 프롬프트에서 python karel.py를 치면 프로그램이 실행된다.
여기서 python 명령은 Python 인터프리터 프로그램을 실행하는 것이고,
인터프리터가 karel.py를 열어서 명령을 읽고 하나씩 처리한다.
인터프리터가 "그것을 읽고 해석해서 실행하는 중간자"다.

4단계별 동작 과정

  1. 파일을 읽기Python 인터프리터가 .py 파일을 위에서부터 읽는다.
  2. 명령을 이해하고 메모리에 기록하기각 줄의 명령을 이해하고 메모리에 변수, 함수 정의 등을 차곡차곡 기록한다.
  3. 시작점에서 실제 실행하기main() 이나 다른 시작점에 도달하면 실제로 명령을 하나씩 실행한다.

PyCharm 설치와 프로젝트, Karel 실행 환경

PyCharm은 코드를 쓰고 실행하고 오류를 찾는 통합 개발 환경으로, 과제 폴더를 프로젝트로 열어 Karel 프로그램까지 바로 실행하는 것이 CS106A의 표준 작업 환경이다.

1상대의 출발점 확인

Python 코드를 쓸 때 단순히 텍스트 편집기(메모장)와 명령 프롬프트로만 작업하면 불편하다.
오타를 찾기 어렵고, 어느 줄에서 오류가 났는지 알기 어렵고,
파일들을 일일이 관리해야 한다.
이런 작업을 편하게 하도록 지원하는 도구가 통합 개발 환경(IDE, 여러 도구가 한 프로그램 안에 들어있는 것)이고,
CS106A에서는 PyCharm을 표준으로 사용한다.

2질문 제기

PyCharm은 무엇을 편하게 만드는가?

3구조적 핵심 예시

PyCharm에서 Assignment1 폴더를 "프로젝트"로 열면,
그 폴더 안의 모든 파일(.py, 이미지, Karel 환경 설정까지)이 한 창에 보인다.
karel.py를 열고 초록색 실행 버튼을 누르면 PyCharm이 자동으로 Python 인터프리터를 실행해서 프로그램을 돌려주고,
오류가 나면 어느 줄인지 정확히 표시해 준다.
명령 프롬프트를 따로 켈 필요도,
경로를 일일이 입력할 필요도 없다.

4단계별 동작 과정

  2. 함수 전달리스트를 함수의 인수로 넘기면, 함수 내부에서 받는 매개변수도 원본 리스트와 같은 객체를 가리킨다. 함수 내에서 리스트를 수정하면 원본이 바뀐다.
  3. 결과한 이름으로 리스트를 수정하면 다른 모든 이름으로도 그 변화가 보인다.

  1. 클라이언트-서버 모델 이해프로그램이 요청과 응답으로 통신한다는 구조를 학습하고, 간단한 웹 서버를 만들어서 브라우저와 상호작용해 봅니다.
  2. 네트워크 데이터 흐름 경험HTTP 요청/응답이 실제로 어떤 형태인지 보고, 데이터가 네트워크를 통해 어떻게 전달되는지 확인합니다.
  3. 윤리적 책임 인식개인정보 보호, 접근성(색상 대비, 화면 읽기 도구 지원), 공정한 알고리즘 설계 같은 윤리적 고려사항을 학습하고, 자신의 코드에 적용하는 연습을 합니다.

CS106A 이후: 시험 대비와 다음 과목

기말 복습으로 배운 것을 정리하고, CS106B 등 다음 과목과 실제 프로그래밍으로 이어 가는 길.

1상대의 출발점 확인

CS106A 과정이 끝나갈 때쯤이면 변수,
함수, 루프, 리스트, 딕셔너리 등 많은 개념을 배웠지만,
이들이 어떻게 체계적으로 연결되고 실제 프로그래밍에서 어떻게 쓰이는지 명확하게 정리하지 않은 채로 과정을 마치게 됩니다.
또한 다음 단계의 CS106B, 인턴십,
또는 개인 프로젝트로 어떻게 나아가야 하는지 방향이 불명확합니다.

2질문 제기

배운 개념들을 어떻게 체계적으로 정리하고, 다음 단계의 프로그래밍 학습으로 어떻게 이어갈 수 있는가?

3구조적 핵심 예시

학습의 진행 방향은 다음과 같습니다.
CS106A에서 배운 변수,
함수, 루프, 리스트, 딕셔너리 같은 기초 개념을 기말고사를 준비하면서 체계적으로 복습하고 정리합니다.
그 다음 CS106B에서는 이들 기초 위에 자료구조(배열, 연결 리스트, 트리),
알고리즘(정렬, 탐색), 효율성 분석을 배웁니다.
최종적으로 실제 프로젝트나 인턴십에서 이 모든 개념을 조합해서 현실적인 문제를 풉니다.

4단계별 동작 과정

  1. 기말고사 준비를 통한 정리강의 노트, 과제, 이전 시험 문제를 검토하면서 핵심 개념(변수 스코프, 함수 설계, 루프 패턴, 리스트와 딕셔너리 활용)을 체계적으로 정리합니다.
  2. CS106B와 심화 과목 선수 지식 확인다음 과목에서 요구하는 선수 지식(재귀, 복잡도 분석, 메모리 관리)이 무엇인지 파악하고, 부족한 부분을 미리 학습합니다.
  3. 실무 프로젝트와 인턴십으로 이어가기개인 프로젝트, 오픈소스 기여, 또는 인턴십을 통해 배운 기술을 실제 환경에서 적용하고, 더 깊이 있는 학습으로 진입합니다.
