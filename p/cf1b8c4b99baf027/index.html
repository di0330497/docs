1출발점 — 자기개선 에이전트라는 문제 설정이후 모든 기법이 '무엇을 무엇으로 개선하는가'라는 루프의 부품이므로, 그 루프의 어휘와 과목 운영 방식을 먼저 세운다.52추론 시점 연산 확장 — 더 많이 뽑는다검증·탐색·RL이 모두 '여러 후보를 뽑아 고른다'는 전제 위에 서므로, 샘플을 늘렸을 때 무엇이 좋아지는지를 먼저 본다.73견고한 검증 — 골라내지 못하면 늘려도 소용없다샘플을 늘려도 정답을 집어내는 장치가 없으면 이득이 사라지므로, 보상·검증 모델을 여기서 확정한다.74도구·코드·피드백으로 배우기자기개선 루프를 닫으려면 모델 밖의 신호가 필요하다. 도구 실행과 AI 피드백이 그 신호원이다.65다단계 추론과 계획 — 한 번의 답이 아니라 긴 궤적실제 에이전트 과제는 여러 행동의 연쇄이므로, 분해·탐색·병렬 실행이라는 궤적 수준의 도구가 필요하다.66학습 시점 확장 — 추론 시점의 이득을 파라미터에 굳히기test-time에서 얻은 개선을 모델 자체에 흡수시키는 경로가 RL이고, 이것이 자기개선 루프를 영구화한다.77메모리와 긴 맥락장기 과제를 반복 수행하려면 경험을 저장하고 되불러와야 하므로, 계획 다음에 기억을 둔다.58검색·심층 연구 에이전트와 개방형 진화외부 지식과 자동 탐색을 붙이면 에이전트가 사람 개입 없이 새 해법을 만들어내는 단계로 넘어간다.79실제 환경의 에이전트 — 소프트웨어 공학과 물리 세계앞의 기법들이 실제 저장소·커널·로봇 환경에서 어떻게 조립되는지를 본다.710평가와 장기 과제 — 개선을 측정할 수 있는가자기개선은 측정 가능한 목표 위에서만 정의되므로, 벤치마크와 평가 설계를 마지막 기술 단계로 둔다.611연구로 연결하기과목의 산출물은 원 연구 프로젝트이므로, 앞의 기법을 실제 연구 절차로 옮기는 방법으로 마무리한다.5

1상대의 출발점 확인

기존의 AI 모델은 학습 후 고정됩니다. 성능을 올리려면 사람이 새로운 데이터를 수집하고 전문가 라벨을 붙이고 모델을 다시 학습시켜야 합니다. 이 과정은 비용이 높고 시간이 오래 걸리며 사람의 개입이 필수적입니다.

2질문 제기

사람이 매번 다시 학습시키지 않으면서 AI 에이전트가 스스로 시도·평가·수정을 반복해 성능을 올릴 수 있을까?

3구조적 핵심 예시

의료 진단 AI: 기존 방식은 모델이 진단을 내리면 끝입니다. CS329A가 다루는 방식은 모델이 진단을 내린 후 그 진단이 맞았는지 관찰하고, 틀린 부분을 분석해 다음 환자에서 같은 실수를 하지 않도록 자신의 추론 방식을 조정합니다.

4단계별 동작 과정

  1. 환경과 상호작용에이전트가 문제를 풀기 위해 행동을 하고, 그 결과를 환경에서 피드백으로 받습니다.
  2. 피드백 평가받은 피드백을 보고 행동이 좋았는지 나빴는지 판단합니다.
  3. 자체 수정평가 결과를 바탕으로 내부 모델이나 전략을 조정해 다음 번 수행을 개선합니다.

1상대의 출발점 확인

LLM은 입력 텍스트를 받으면 출력 텍스트만 생성합니다. 외부 세계의 변화나 자신의 행동이 미친 실제 영향을 인식하지 못하고, 다음 번 호출 때도 그 전의 결과를 반영하지 않습니다.

2질문 제기

LLM이 환경과 상호작용하며 자신의 행동 결과를 보고 판단하려면 어떤 기본 개념들이 필요할까?

3구조적 핵심 예시

로봇 팔이 물건을 집는 작업: LLM은 "물건을 집으세요"라는 명령을 내리지만, 그 명령이 성공했는지 실패했는지 모릅니다. 에이전트는 명령(행동)을 내린 후 "물건을 집었습니까?" 라는 센서 신호(관측)를 받고, 실패했다면 왜 실패했는지를 다음 시도에 반영합니다.

4단계별 동작 과정

  1. 환경에이전트가 상호작용하는 외부 시스템 (API, 데이터베이스, 물리 시스템 등).
  2. 행동-관측 쌍에이전트가 환경에 명령(행동)을 하고, 그 결과를 피드백(관측)으로 받으며, 이 쌍이 반복됩니다.
  3. 궤적이 행동-관측 쌍들을 시간 순서대로 기록한 것으로, 에이전트가 어떤 상황에서 어떻게 행동했고 무엇을 얻었는지 보여줍니다.

자기개선의 두 축: 추론 시점(test-time) 개선과 학습 시점(train-time) 개선

답을 낼 때 더 많이 생각해 좋아지는 방식과, 그 경험으로 모델 가중치를 다시 학습해 좋아지는 방식 두 갈래가 있다.

1상대의 출발점 확인

전통적으로 AI 개선은 학습 시점(train-time)에만 일어났습니다. 배포된 모델은 수정할 수 없고, 성능을 올리려면 새 데이터를 모아 처음부터 다시 학습시켜야 했습니다.

2질문 제기

에이전트가 답을 낼 때(추론 시점)와 모델을 학습할 때(학습 시점), 두 순간 각각에서 어떻게 개선될 수 있을까?

3구조적 핵심 예시

수학 문제 풀기: 추론 시점 개선은 같은 문제를 여러 풀이 방식으로 시도해서 가장 잘 작동하는 풀이를 고르는 것 (즉시 이득). 학습 시점 개선은 그 성공한 풀이들을 모아서 모델을 재학습시켜 처음부터 그 방식을 선호하게 만드는 것 (장기 이득).

4단계별 동작 과정

  1. 추론 시점 개선같은 문제를 여러 방식으로 시도하고, 그중 검증을 통과한 좋은 답을 최종 출력합니다 (즉시 성능 향상).
  2. 학습 시점 개선추론 시점에서 성공한 답변들을 수집하여 모델의 가중치를 조정합니다 (장기 성능 향상).
  3. 두 축의 상호작용추론에서 얻은 좋은 사례가 학습 데이터가 되고, 재학습된 모델이 다음 추론을 더 좋게 만듭니다.

3구조적 핵심 예시

  3. 예측 적용적은 수의 시행 데이터로 많은 샘플링의 성공률을 수학적으로 예측하고, 비용 대비 효율이 최대인 샘플 수를 계획할 수 있습니다.

  1. 후속 풀이 생성각 중간 단계 이후로 동일한 문제를 모델이 여러 번(N회) 다시 풀이
  2. 성공률 계산그 N회 중 몇 개가 최종 정답에 도달했는지 확인
  3. 자동 라벨 부여성공률을 그 단계의 품질 점수로 삼아 PRM 학습 데이터로 활용

2질문 제기

3구조적 핵심 예시

4단계별 동작 과정

  1. 코드/증명 실행제안된 코드를 실제 실행 환경에서 돌리거나, 형식 증명기(정리 증명기)로 정확성을 검증 시도
  2. 결과 수집성공 여부, 오류 메시지, 테스트 통과/실패 기록
  3. 피드백 활용실제 실행 결과를 모델의 문맥에 되먹이거나 검증 신호로 사용해 다음 생성 개선

  3. 분포 이동 감지생성된 답의 통계적 특성(단어 빈도, 구조 등)이 원래 데이터와 벗어남을 감지

4단계별 동작 과정

  1. 추론 단계현재 상황과 가진 정보를 분석해 다음에 무엇을 할지 결정
  2. 행동 단계검색, 계산기, 코드 실행, 데이터베이스 조회 등 도구 호출
  3. 관측 반영도구의 반환 결과를 에이전트의 문맥 정보에 추가하고 루프 재시작

코드를 도구로 쓰기: 실행 결과를 근거로 삼는 추론

답을 글로 추측하는 대신 코드를 짜서 실행하고, 그 실행 결과를 검증 가능한 근거로 삼아 추론하는 방법.

1상대의 출발점 확인

기존에는 모델이 문제를 받으면 바로 답을 글로 작성한다. 예를 들어 복잡한 수학 문제를 받으면 계산 과정을 문자로 풀어서 적거나, 추론이 필요한 질문을 받으면 말로 생각을 정리해서 답한다. 이 방식의 문제는 실제로 검증할 방법이 없다는 점이다. 답이 논리적으로 그럴듯해 보이지만, 정말 맞는지 확인할 수 없다. 모델이 계산을 틀리거나 가정을 잘못했을 가능성이 높은데도, 그냥 글로 쓴 답을 근거로 삼을 수밖에 없다.

2질문 제기

실행 가능한 코드를 직접 짜서 실행한 결과를 보면, 추측이 아닌 사실로 답을 검증할 수 있지 않을까?

3구조적 핵심 예시

예를 들어 "리스트에서 가장 자주 나오는 원소가 무엇인가?"라는 문제가 있다면, 기존에는 "Counter를 쓰면 된다"고 말하기만 한다. 하지만 코드를 도구로 쓰면, Python에서 Counter([1, 2, 2, 3, 3, 3]).most_common(1)을 실행하고, 화면에 [(3, 3)]이 나오는 결과를 직접 본다. 이제 답이 "말"이 아니라 "실행된 프로그램의 출력"이 된다. 틀렸으면 출력이 다르게 나오고, 바로 고칠 수 있다.

4단계별 동작 과정

  1. 코드 작성모델이 문제를 풀기 위한 코드를 직접 작성한다.
  2. 코드 실행그 코드를 실제로 실행하고 결과를 얻는다.
  3. 결과 검증실행된 출력값(숫자, 텍스트, 참/거짓 등)을 근거로 답이 맞는지 판단하고, 틀렸으면 코드를 수정한다.

실행 피드백 강화학습 RLEF

코드 실행과 테스트 통과 여부를 보상으로 삼아 모델을 강화학습으로 다듬어, 피드백에 따라 스스로 고치게 만드는 기법.

1상대의 출발점 확인

기존 모델 학습은 사람이 정답과 오답을 미리 정하고, 모델이 정답을 맞히면 보상을 주고 오답을 맞히면 벌칙을 준다. 하지만 이 방식은 사람이 일일이 채점해야 하고, "더 나은 답"을 정의하기도 애매하다. 예를 들어 코드 문제에서는 실행 결과가 정확히 맞는지 아닌지만 객관적으로 판단할 수 있는데, 기존 학습은 그런 객관적 신호를 충분히 활용하지 않는다.

2질문 제기

3구조적 핵심 예시

모델이 "주어진 숫자들의 합을 구하는 함수"를 작성했다고 하자. 그 함수를 테스트 케이스 10개에 대해 실행한다. 8개는 통과하고 2개는 실패했다면, 그 실행 결과(통과율 80%, 어느 케이스가 실패했는지)를 학습 신호로 삼는다. 모델은 이 신호를 받아 코드를 수정한다. 이것을 반복하면, 모델은 자연스럽게 테스트를 더 많이 통과하도록 개선된다.

4단계별 동작 과정

  1. 코드 생성과 실행모델이 코드를 짜고, 미리 정해진 테스트 케이스들을 실행한다.
  2. 보상 계산통과한 테스트 개수나 통과율을 보상값으로 계산한다.
  3. 강화학습으로 갱신그 보상값을 바탕으로 모델의 가중치를 조정해, 다음엔 더 나은 코드를 생성하도록 유도한다.

1상대의 출발점 확인

2질문 제기

3구조적 핵심 예시

"모델이 생성한 답이 정직한가?", "사실에 기반한가?", "해로운 내용은 없는가?"라는 원칙 목록(헌법)을 정한다. 그 다음 다른 AI 평가 모델을 두고, 각 답에 대해 이 원칙들을 체크하게 한다. 예를 들어 모델의 답이 거짓 정보를 포함했다면, 평가 모델이 그 부분을 지적하고 수정된 버전을 제시한다. 이 과정이 사람의 개입 없이 자동으로 일어난다.

4단계별 동작 과정

  1. 답 생성모델이 질문에 대한 답을 생성한다.
  2. 원칙 기반 평가별도의 평가 모델이 정해진 원칙들을 기준으로 그 답을 비평하고, 문제점을 지적한다.
  3. 자동 수정 및 학습평가 모델이 지적한 부분에 따라 답을 수정한 결과를 학습 데이터로 사용한다.

모델이 복잡한 문제를 받으면, 보통은 단계를 밟지 않고 바로 답을 생성하려 한다. 또는 생각하며 진행하되, 각 단계를 미리 계획하지 않고 매번 다음 단계를 즉흥적으로 결정한다. 이 방식은 복잡한 문제에서는 길을 잃기 쉽다. 예를 들어 여러 단계가 연결되어야 하는 작업에서, 앞의 결정이 뒤의 선택지를 크게 제약하는데도 이를 고려하지 않고 진행할 수 있다.

2질문 제기

  1. 문제 분석주어진 복잡한 문제를 여러 작은 하위 과제로 나눈다.
  2. 순서 결정그 하위 과제들 사이의 의존성을 파악해, 실행 순서를 미리 정한다.
  3. 순차 실행정해진 순서에 따라 각 하위 과제를 하나씩 실행하고, 그 결과를 다음 단계에 전달한다.

1상대의 출발점 확인

지금까지의 기법은 한 번 결정한 순서대로 진행했다. 하지만 실제로는 각 단계에서 여러 선택지가 있고, 어떤 선택이 나중에 어떤 결과를 낼지 미리 알 수 없다. 예를 들어 "이동할 경로"를 결정할 때, A 경로로 가면 막히고 B 경로로 가면 뚫려 있는데, 미리 어느 것이 나을지 알 수 없다. 이런 상황에서는 한 번의 계획으로 충분하지 않다.

2질문 제기

가능한 행동들을 모두 펼쳐 보고, 유망한 가지를 집중적으로 탐색하면서 계획을 세울 수 있을까?

3구조적 핵심 예시

체스 엔진을 생각해 보자. 현재 체스판 상태에서 취할 수 있는 모든 수(행동)를 가지로 그린다. 각 가지마다 다음에 가능한 상대 수를 또 가지로 그린다. 이렇게 트리를 펼쳐 놓되, 모든 가지를 깊게 탐색하는 대신, 몬테카를로 트리 탐색(MCTS)으로 유망한 가지들을 집중적으로 파고, 예상되는 승률이 높은 수를 고른다. 이 과정이 결국 "계획"이다.

4단계별 동작 과정

  1. 트리 구성현재 상태에서 취할 수 있는 모든 행동을 가지로 그리고, 각 행동 후의 가능한 결과 상태들을 재귀적으로 펼쳐 나간다.
  2. 선택적 탐색몬테카를로 트리 탐색으로 가능성이 높은 가지들을 더 깊게 탐색하고, 그 경로의 예상 값(승률, 보상)을 평가한다.
  3. 추론·행동·평가 루프각 단계에서 "다음 행동을 무엇으로 할지" 추론하고, 그 행동을 가상 또는 실제로 실행한 뒤, 그 결과를 평가해 다시 탐색에 반영한다.

5본질 요약

1상대의 출발점 확인

현재 모델들은 모든 문제에 동일한 양의 추론 계산을 사용합니다. 예를 들어 어떤 모델은 항상 같은 깊이로 생각하거나 항상 같은 수의 후보를 탐색합니다. 하지만 문제마다 난이도가 크게 다릅니다. 어떤 문제는 적은 계산으로도 정답에 도달하지만, 어떤 문제는 깊고 광범위한 탐색이 필요합니다. 현재 방식은 쉬운 문제에는 과다 계산을 하고, 어려운 문제에는 불충분한 계산을 할 가능성이 높아 전체 효율이 낮습니다.

3구조적 핵심 예시

추론 진행 중 현재까지의 여러 후보 답변들의 확신도(각 답변이 정답일 확률)를 평가합니다. 만약 가장 유망한 후보의 확신도가 이미 충분히 높으면 그 경로를 더 깊게 탐색하고, 확신도가 낮고 불확실하면 완전히 다른 새 후보들을 더 생성하여 폭넓게 탐색합니다.

4단계별 동작 과정

  1. 초기 병렬 탐색여러 가능한 풀이 경로를 동시에 시작해 각각 몇 단계씩 진행하면서 초기 후보군을 구성합니다.
  2. 적응적 판단각 경로의 현재 확신도를 평가하여, 유망한 경로는 같은 방향으로 더 깊게 계속 진행할지, 불확실한 경로는 완전히 다른 새로운 후보를 추가로 생성할지를 결정합니다.
  3. 선택적 심화최종 선택된 경로들을 필요한 만큼만 더 계산해 최종 답을 도출합니다.

계획과 실행의 병렬화: SPRINT

긴 추론을 순차로만 흘리지 않고, 서로 의존하지 않는 하위 단계를 찾아 계획과 실행을 번갈아·동시에 진행해 지연을 줄이는 방법이다.

1상대의 출발점 확인

현재 추론 방식은 순차적입니다. A 단계를 완료해야 B 단계를 시작하고, B가 완료되어야 C를 시작합니다. 이 방식에서 전체 처리 시간은 모든 단계의 시간을 더한 값이 됩니다. 복잡한 작업은 단계가 많을수록 지연이 누적되어 전체 시간이 매우 길어집니다.

2질문 제기

서로 의존하지 않는 추론 단계들을 동시에 진행할 수 있을까요?

3구조적 핵심 예시

어떤 복잡한 문제에서 "필요한 데이터 수집", "해결책 알고리즘 검토", "테스트 케이스 작성" 같은 하위 작업들이 각각 독립적이면, 이들을 순차로 진행하지 않고 동시에 시작해 병렬로 처리한 후, 필요할 때마다 그 결과들을 조합합니다.

4단계별 동작 과정

  1. 의존성 분석전체 추론 과정을 여러 하위 단계로 쪼개고 각 단계 간의 의존성을 파악하여 어느 단계들이 서로 독립적인지 식별합니다.
  2. 병렬 실행독립적인 단계들을 동시에 시작해 각각 진행합니다.
  3. 결과 조합과 피드백완료된 단계들의 결과를 조합하고, 필요하면 추가적인 독립 단계를 더 병렬로 시작합니다.

다단계 궤적을 학습으로 되먹이기: SWiRL

여러 단계에 걸친 추론·도구 사용 궤적을 합성 데이터로 모아 단계별 강화학습으로 되먹여, 에이전트의 계획 능력 자체를 개선하는 기법이다.

1상대의 출발점 확인

현재 모델들은 사전 학습 이후 파라미터가 고정되거나, 최종 결과에 대한 피드백(정답 또는 오답)만 받습니다. 하지만 추론 과정은 여러 단계의 의사결정으로 이루어집니다. 한 단계에서 잘못된 선택을 하면 나중 단계에서 돌이킬 수 없고, 중간 단계의 오류는 학습 신호에 반영되지 않아 모델이 더 나은 계획 전략을 배우지 못합니다.

2질문 제기

추론 과정의 각 단계마다 피드백을 받아 에이전트가 스스로 더 좋은 계획을 세울 수 있도록 학습할 수 있을까요?

3구조적 핵심 예시

에이전트가 문제를 푸는 전체 과정(도구 선택 → 실행 → 결과 확인 → 다음 단계 결정)을 처음부터 끝까지 기록하고, 최종 성공 여부뿐 아니라 각 중간 단계가 최종 성공에 얼마나 기여했는지를 평가하는 신호를 학습에 사용합니다.

4단계별 동작 과정

  1. 궤적 수집에이전트가 문제를 푸는 전 과정을 기록합니다 (선택한 도구, 도구 실행 결과, 상태 변화 등).
  2. 단계별 평가각 중간 선택이 최종 성공에 미친 영향을 평가합니다 (예: 이 도구 선택이 없었다면 실패했을까).
  3. 강화학습 적용각 단계별 평가 결과를 바탕으로 좋은 선택은 강화하고 나쁜 선택은 약화시켜 모델 파라미터를 업데이트합니다.

자기 생성 데이터로 학습하기: STaR의 부트스트랩과 합리화

모델이 스스로 만든 풀이 중 정답에 이른 것만 모아 다시 학습하고, 틀린 문제는 정답을 힌트로 줘 사후 합리화한 풀이를 추가해 추론 능력을 부트스트랩하는 방법.

1상대의 출발점 확인

현재 모델들은 대부분 사람이 작성한 정답 풀이로만 학습합니다. 학습 데이터는 수집 시점에 고정되고, 그 이후 모델이 자신의 약점을 반복적으로 개선할 기회가 없습니다. 또한 고품질 학습 데이터 수집에는 사람의 시간과 비용이 많이 소요됩니다.

2질문 제기

모델이 스스로 만든 풀이를 활용해 자동으로 학습 데이터를 생성하고 개선하면서 능력을 키울 수 있을까요?

3구조적 핵심 예시

현재 모델이 어떤 문제를 여러 번 풀어보게 하고, 정답에 도달한 풀이는 학습 데이터에 추가합니다. 틀린 풀이는 정답을 일부 공개한 후 그 정답을 어떻게 유도했는지 다시 작성하게 하고, 이 개선된 풀이(사후 합리화)도 학습 데이터에 포함시킵니다.

4단계별 동작 과정

  1. 자기 풀이 생성현재 모델이 같은 문제를 여러 번 풀어 다양한 풀이 시도를 생성합니다.
  2. 정답 풀이 수집정답에 도달한 풀이만 따로 모아 새로운 학습 데이터로 추가합니다.
  3. 사후 합리화와 재학습틀린 풀이는 정답 힌트를 제공하고 다시 작성하게 해서, 그 개선된 풀이도 학습 데이터에 포함시킨 후 모델을 재학습합니다.

1상대의 출발점 확인

거절 샘플링은 여러 번 생성한 답 중 검증(예: 정답 판정)을 통과한 것만 학습에 사용하는 방식으로, 필터링된 고품질 데이터로 모델을 개선합니다. 처음에는 효과적이지만, 같은 방식을 여러 번 반복하면 문제가 발생합니다. 모델이 계속 비슷한 패턴만 생성하게 되고, 다양성이 손실되며, 이는 결국 성능 저하로 이어집니다.

3구조적 핵심 예시

처음 반복에서는 모델이 다양한 방식으로 풀이를 시도하고, 정답인 것들만 필터링해 미세조정하면 학습이 잘 진행됩니다. 하지만 같은 방식으로 반복하다 보면 모델이 점점 비슷한 구조와 패턴의 풀이만 생성하기 시작해, 필터링된 학습 데이터 자체의 다양성이 급격히 감소합니다.

4단계별 동작 과정

  2. 중간 반복 (3~5차)점점 같은 형태의 풀이만 생성되기 시작해, 필터링된 학습 데이터의 다양성이 눈에 띄게 감소합니다.

1상대의 출발점 확인

모델을 순수 언어 모델링 손실(다음 단어 예측 오차)만으로 학습하면, 모델은 다음 단어 예측에만 최적화됩니다. 하지만 실제로 필요한 것은 사람이 원하는 답변 생성, 특정 요청 거절, 안전한 응답 등 훨씬 복잡한 행동입니다. 단순 예측 목표만으로는 이런 미묘하고 복합적인 요구사항을 모델에 체계적으로 임베딩할 수 없습니다.

2질문 제기

3구조적 핵심 예시

4단계별 동작 과정

  1. 지도 미세조정(SFT)사람이 작성한 고품질의 명령과 답변 쌍으로 모델을 미세조정해 기본적인 명령 수행 능력을 확보합니다.
  2. 보상모델 학습미세조정된 모델의 여러 답변 쌍을 사람에게 보여줘 선호도를 수집하고, 그 데이터로 어떤 답변이 "좋은지" 를 점수로 예측하는 보상모델을 학습합니다.
  3. PPO 강화학습보상모델의 신호를 바탕으로 정책 경사 강화학습 알고리즘(PPO)을 적용해, 높은 보상을 받는 답변을 생성하는 쪽으로 모델의 정책을 반복적으로 업데이트합니다.

1상대의 출발점 확인

일반적인 RL 학습은 모델 출력을 샘플링하고, 보상에 따라 손실값을 계산해 역전파하는 방식입니다. 그런데 규모가 커지면 문제가 생깁니다. 일부 샘플에서 나온 손실값이 매우 크면 그 업데이트가 모델을 크게 틀어뜨립니다. 또한 정확한 답만 계속 학습하면 모델이 출력을 단일화하고, 긴 답에 높은 보상을 주면 모델은 불필요하게 길게 답합니다. 롤아웃(샘플링)과 학습을 동시에 돌리는 인프라 비용도 병목입니다.

3구조적 핵심 예시

DAPO는 네 가지 방식을 함께 적용합니다. 첫째, 손실값이 너무 크면 일정 크기 이상으로 자르기(비대칭 클리핑). 둘째, 답을 맞춘 그룹과 틀린 그룹을 따로 다루되, 섞여 있는 샘플은 제외. 셋째, 문장 단위가 아닌 토큰 단위로 손실을 계산해 긴 부분에 과도한 가중치가 실리지 않도록 함. 넷째, 보상값이 비정상적으로 높은 경우를 조정.

4단계별 동작 과정

  1. 학습 전 데이터 필터링응답이 완전히 맞거나 완전히 틀린 샘플만 선별. 부분적으로 맞는 경우는 제외해 신호를 명확하게 함.
  2. 손실 계산 및 제어토큰별로 손실을 계산하고, 비정상적으로 큰 손실값은 클리핑. 길이가 긴 응답이 손실을 지배하지 않도록 함.
  3. 모델 업데이트제어된 손실값으로 역전파해 매개변수를 안정적으로 업데이트.

1상대의 출발점 확인

기본적인 RL 학습은 좋은 답에 더 높은 확률을 주도록 모델을 업데이트합니다. 이것 자체는 합리적이지만, 규모를 키워 오래 학습하면 세 가지 문제가 동시에 나타납니다. 첫째, 정확도가 높은 특정 답만 계속 강화하면 모델이 다른 가능성을 탐색하지 않게 되고 출력 다양성이 사라집니다(엔트로피 붕괴). 둘째, 보상이 응답 길이와 양의 상관관계가 있으면 모델은 점점 더 길게 답합니다(길이 폭주). 셋째, 수백만 개의 롤아웃을 생성하고 동시에 학습해야 하는 인프라 비용이 막대합니다.

2질문 제기

3구조적 핵심 예시

초기 모델이 "빨강, 파랑, 초록" 중 하나를 답하는 분류 문제에서, "파랑"이 정답일 때 RL은 파랑의 확률을 높입니다. 반복하면 모델이 99%의 확률로 파랑만 선택. 다른 두 색을 선택할 가능성은 거의 1%가 되어 다양성이 사라집니다. 동시에 보상 함수가 긴 설명을 더 높이 평가하면 모델은 자꾸만 설명을 늘립니다.

4단계별 동작 과정

  1. 엔트로피 붕괴특정 답에 집중하면서 다른 가능성의 확률이 극도로 낮아짐. 모델이 탐색을 멈추고 반복만 함.
  2. 길이 폭주보상이 응답 길이와 상관관계가 있으면 모델이 의도적으로 불필요한 내용을 추가. 토큰 사용량 증가.
  3. 인프라 병목수백만 개의 샘플을 생성하고 학습하는 데 필요한 계산 자원이 기하급수적으로 증가.

4단계별 동작 과정

  3. 모델 파라미터 최적화학습을 통해 모델이 추론 시 다중 샘플링 없이도 유사한 성능을 내도록 매개변수 업데이트.

모델이 한 번에 볼 수 있는 토큰 수는 유한하므로, 외부에서 필요한 조각을 찾아오는 RAG와 에이전트가 스스로 쌓고 다듬는 메모리를 구분해 다뤄야 한다.

1상대의 출발점 확인

LLM은 한 번에 처리할 수 있는 토큰 수가 정해져 있습니다(4K, 8K, 128K, 200K 등). 만약 모든 정보를 컨텍스트에 넣으려 하면 창 크기를 초과합니다. 따라서 필요한 정보만 선택적으로 가져와야 합니다. 전통적으로 모든 외부 정보 검색 문제를 하나로 다뤘지만, 실제로는 두 가지 다른 방식이 있습니다. RAG는 외부 저장소(데이터베이스, 문서)에서 명시적으로 검색하는 것이고, 에이전트 메모리는 대화 중에 모델 자신이 중요한 정보를 골라 저장하고 압축하는 것입니다.

2질문 제기

유한한 컨텍스트에서 어떤 정보는 외부에서 검색하고 어떤 정보는 에이전트가 스스로 기억해야 할까요?

3구조적 핵심 예시

사용자가 긴 보고서(예: 200페이지)를 올리고 질문하는 경우를 생각해봅시다. RAG 방식이면 검색 엔진이 "이 질문과 관련된 페이지 3개"를 찾아 그 부분만 컨텍스트에 넣습니다. 에이전트 메모리 방식이면 대화 중에 모델이 "사용자가 지속적으로 묻는 핵심 개념은 X, Y, Z다"라고 판단해 압축해 저장해둡니다. 첫 번째는 문서 외부에서 끌어오는 것, 두 번째는 대화 자체에서 추출하고 경량화하는 것입니다.

4단계별 동작 과정

  1. 컨텍스트 창 제약 인식모델이 한 번에 볼 수 있는 토큰 한도 설정. 필요한 정보 전체를 넣을 수 없음을 파악.
  2. RAG를 통한 외부 정보 검색사용자 질문을 기반으로 외부 저장소에서 관련 정보만 검색해 컨텍스트에 추가.
  3. 에이전트 메모리를 통한 대화 압축대화 기록에서 반복되는 개념이나 사용자 의도를 인식해 경량 표현으로 저장.

MemGPT: 가상 컨텍스트와 OS식 페이징

1상대의 출발점 확인

LLM의 컨텍스트 창은 고정 크기입니다. 대화가 길어지면 처리할 토큰이 늘어나 창 한도에 도달합니다. 이때 보통 옛날 메시지는 버립니다. 그러나 운영체제의 가상 메모리 개념을 생각해보면 다릅니다. OS는 실제 RAM 크기보다 크게 프로그램이 사용 가능한 메모리 공간을 제공합니다. 필요할 때만 디스크에서 메모리로 가져오는 페이징 메커니즘을 통해 말입니다. 이 아이디어를 LLM 컨텍스트에 적용할 수 있습니다.

2질문 제기

컨텍스트 창을 주기억장치로 보고 외부 저장소를 보조기억장치로 삼아 유사 무한 대화를 유지할 수 있을까요?

3구조적 핵심 예시

컨텍스트 창이 8K 토큰이라고 하면 현재 활성 정보 8K 토큰만 모델에 보입니다. 그보다 오래된 대화(예: 100K 토큰)는 외부 저장소(메모리 뱅크)에 저장되어 있습니다. 모델이 오래된 정보가 필요하면(예: "아까 말한 그 개념이 뭐였지?") 명시적으로 그것을 요청하고, 시스템이 저장소에서 꺼내와 현재 창에 넣습니다. OS의 페이지 폴트처럼 필요할 때만 불러옵니다.

4단계별 동작 과정

  1. 활성 컨텍스트 창 유지현재 대화에 필요한 최근 정보(8K 등)만 모델에 제공. 이것을 주기억장치로 취급.
  2. 오래된 정보 외부 저장창을 초과하는 이전 메시지나 정보는 외부 저장소에 압축해 저장.
  3. 필요에 따라 회수 및 통합모델이 오래된 정보 필요를 나타내면 저장소에서 찾아 현재 창에 통합.

Cartridges: 자가학습으로 만든 경량 장기 컨텍스트 표현

긴 문서를 매번 통째로 넣는 대신, 자가학습으로 미리 압축해 둔 작은 KV 표현(카트리지)을 끼워 넣어 같은 지식을 훨씬 싸게 쓰는 방법이다.

1상대의 출발점 확인

RAG에서 문서를 검색한 후 그 문서를 모델의 입력으로 넣으려면 문서 전체를 토크나이즈하고 처리해야 합니다. 만약 문서가 길면 많은 토큰이 소비되고, 계산이 오래 걸립니다. 그런데 시간이 지나 같은 문서가 또 검색되어도 매번 처음부터 처리합니다. 이는 비효율적입니다. 미리 문서를 처리해 핵심만 압축해두면 나중에 훨씬 빠르게 재사용할 수 있습니다.

2질문 제기

긴 문서를 매번 전체로 처리하지 않고 압축된 표현으로 효율적으로 재사용할 수 있을까요?

3구조적 핵심 예시

긴 문서(예: 50 페이지)를 미리 모델에 통과시켜 그 과정에서 계산된 KV 캐시(key-value 캐시, 각 토큰의 숨겨진 표현)를 저장해둡니다. 이것이 카트리지입니다. 나중에 "이 문서로 질문에 답하기"라는 작업이 들어오면 50페이지 전체를 다시 처리하지 않고, 미리 저장한 작은 KV 표현만 로드해서 사용합니다. 원본 문서(매우 길고 무겁다) 대신 카트리지(작고 가볍다)를 사용하는 것입니다.

4단계별 동작 과정

  1. 사전 처리 및 KV 추출긴 문서를 모델에 통과시켜 각 토큰의 KV 캐시 계산. 결과를 저장(카트리지 생성).
  2. 경량 표현 저장카트리지(수백 토큰)를 저장소에 저장. 원본 문서(수천 토큰)는 버리거나 별도로 보관.
  3. 추론 시 카트리지 로드 및 활용질문이 들어오면 카트리지를 메모리에 로드해 모델이 직접 처리. 원본 처리 비용 없음.

CacheBlend: KV 캐시 융합으로 RAG 지연 줄이기

여러 문서의 미리 계산된 KV 캐시를 재사용하고 일부만 다시 계산해 합침으로써 RAG 응답의 첫 토큰 지연을 크게 줄이는 서빙 기법이다.

1상대의 출발점 확인

RAG 시스템에서 사용자 질문이 들어오면 관련 문서를 검색한 후 그 문서들을 모델에 입력합니다. 여러 문서를 한 번에 처리해야 하므로 프롬프트(시스템 지시문 + 검색된 문서들 + 사용자 질문)가 매우 길어집니다. 모델이 이 긴 프롬프트를 모두 처리한 후에야 첫 응답 토큰을 생성할 수 있습니다. 이를 첫 토큰 지연(Time To First Token, TTFT)이라 하며, 사용자 체감 속도에 큰 영향을 줍니다.

2질문 제기

3구조적 핵심 예시

자주 검색되는 100개의 문서(예: 제품 가이드, FAQ 등)에 대해 사전에 KV 캐시를 계산해둡니다. 사용자 질문이 들어오고 이 100개 중 30개가 검색 결과로 나왔다고 하면, 30개의 미리 계산된 캐시를 그대로 로드합니다(30개는 0비용). 새로 검색된 문서 5개만 처음부터 처리합니다(5개만 계산). 결과적으로 35개 문서 전체를 처음부터 처리하는 것(35개 계산)보다 훨씬 빠릅니다.

4단계별 동작 과정

  1. 자주 사용되는 문서의 KV 캐시 사전 계산상위 N개 문서에 대해 미리 KV 캐시 계산하고 저장.
  2. 검색 결과와 캐시 비교새 질문의 검색 결과 중 이미 캐시된 문서는 재사용, 없던 문서는 새로 계산.
  3. 캐시된 부분과 새 계산 부분 합성재사용 캐시와 새 계산 결과를 함께 사용해 응답 생성.

LLM이 모든 이전 토큰을 메모리에 그대로 유지한다면 어떻게 될까요? 메모리 크기는 한정되어 있고, 계산량도 늘어나며, 처음 10개 턴의 대화는 마지막 처리 결정에 거의 영향을 주지 않습니다. 현실의 메모리는 무한하지 않으므로, 정보를 모두 저장하는 것은 불가능합니다.

2질문 제기

무한히 증가하는 정보를 어떻게 일정 크기의 메모리 안에 효율적으로 담으면서도 필요한 내용은 보존할까요?

3구조적 핵심 예시

100개 턴의 대화 기록이 있는데 앞의 10개 턴은 문맥상 덜 중요하다면, 그것들을 "초기 단계에서 목표와 배경 설정"이라는 1-2줄 요약으로 압축하고, 나머지 90개는 전체 보존하는 방식입니다.

4단계별 동작 과정

  1. 요약·압축(summarization)오래되고 중요도가 낮은 구간을 몇 줄의 요약으로 축약해 공간 절약.
  2. 우선도 필터링(priority filtering)남은 정보 중에서도 현재 작업과 무관한 것들을 제거.
  3. 순환 버퍼(rotating buffer)메모리 한계에 도달하면 가장 오래된 것부터 삭제하고 새 정보 추가.

1상대의 출발점 확인

프로그래밍 대회 문제를 풀려면 한 번에 정확한 코드를 생성해야 한다고 생각합니다. 하지만 대회 문제는 복잡하고 엣지 케이스가 많아서 한 번의 생성으로 맞히기 어렵습니다. 정확도를 높이려면 여러 시도가 필요한데, 사람은 한 번에 하나씩만 만듭니다.

2질문 제기

하나의 정확한 답 대신 수백만 개 후보를 생성한 뒤 거르면 올바른 답을 찾을 확률이 훨씬 높을까요?

3구조적 핵심 예시

  2. 테스트 필터링(test filtering)각 코드를 제공된 예제 입출력으로 실행해 통과한 것만 유지.
  3. 클러스터링·중복 제거(clustering)남은 코드들을 실행 결과로 묶어, 동작이 동일한 것끼리 그룹화한 뒤 각 그룹의 대표만 남김.

1상대의 출발점 확인

2질문 제기

  3. 정보 종합·보고서 생성(synthesis & report generation) — 수집된 답변들을 논리적으로 정리하고 출처를 표기해 최종 보고서 작성.

1상대의 출발점 확인

4단계별 동작 과정

  2. 샘플링해당 파일들에 대해 테스트 케이스와 수정 방안을 여러 개 생성합니다(한 가지가 아니라 5개, 10개 등).

  3. 종합 평가정확성 점수와 성능 점수를 결합해 최종 점수를 도출합니다.

4단계별 동작 과정

  1. 격리된 실행 환경샌드박스(독립된 실행 공간)에서 에이전트가 생성한 코드를 실행해 악의적이거나 위험한 코드로부터 시스템을 보호합니다.
  2. 코드 탐색·검색 도구에이전트가 저장소에서 필요한 파일, 함수, 클래스를 검색해 문맥을 수집할 수 있게 합니다.
  3. 실행 피드백과 회귀 테스트코드 실행 결과를 에이전트에게 전달하고, 기존 테스트를 실행해 새 수정이 기존 기능을 깨뜨리지 않았는지 검증합니다.

1상대의 출발점 확인

3구조적 핵심 예시

  3. 다층 자동 채점인용 검증(논문이 실제 존재하는가), 사실성 검증(논문의 주장이 정확한가), 논리 검증(주장들이 일관성 있게 연결되었는가)을 수행한다.

사람이 모든 모델 출력을 채점하는 것은 너무 오래 걸리고 비싸다. 그래서 "GPT-4를 채점자로 쓰자"는 아이디어가 나왔지만, 같은 모델 계열이 모델을 채점하면 편향이 생긴다. 자신의 출력 스타일을 더 높게 평가하게 되는 것이다. 더 심각하게, 벤치마크 문제가 학습 데이터에 포함되면, 모델이 진짜 능력이 아니라 암기를 채점받는다.

2질문 제기

모델이 모델을 채점할 때 신뢰할 수 있고, 벤치마크 자체가 오염되지 않으려면 어떻게 해야 하는가?

3구조적 핵심 예시

GPT-4가 모델 A의 답을 "훌륭함"이라 평가하는데, 실제로는 "훌륭함"이란 GPT-4 자신의 답 스타일과 가까운 것을 뜻할 수 있다. 모델 A가 더 짧고 직설적인 답을 내놓으면 GPT-4는 낮게 평가하지만, 모델 A가 GPT-4처럼 장황하고 세심한 답을 내놓으면 높게 평가한다. 동시에 벤치마크 문제가 GPT-4의 학습 데이터에 섞여 있으면, GPT-4는 채점이 아니라 사실상 암기를 평가한다.

4단계별 동작 과정

  1. 채점자 편향LLM-as-judge가 같은 계열이나 훈련 데이터가 비슷한 모델을 평가하면, 자신의 스타일과 가까운 답을 높게 평가하는 편향이 생긴다. 이를 포착하려면 다양한 채점자(사람, 다른 계열 모델)를 함께 사용해야 한다.
  2. 벤치마크 오염 감지벤치마크 문제들을 학습 데이터 공개 시점과 비교해서, 채점 대상 모델의 학습 시간에 그 문제가 포함되었는지 확인한다.
  3. 신뢰 가중치 조정편향 위험이 높거나 오염 가능성이 있는 채점은 가중치를 낮추고, 독립적인 인간 채점 결과와 비교해 LLM 채점의 신뢰도를 재조정한다.

3구조적 핵심 예시

오케스트레이션 프레임워크는 사용자의 요청이 들어오면, "이 요청은 2초 이내에 답해야 하고, 토큰 예산은 5000개"라는 제약 하에서 다음을 자동으로 결정한다: 첫 시도 후 검증이 필요한가 → 검증이 필요하면 수정 시도는 몇 번 → 최종 검증은 어느 수준인가. 이 과정에서 비용과 지연을 동시에 최소화하는 경로를 찾는다.

4단계별 동작 과정

  2. 전략 구성 최적화모델이 초기 시도 횟수, 각 검증 단계, 수정 반복 횟수를 비용-품질 함수에 따라 자동 계산해서, 예산 안에서 기댓값 최대화 전략을 선택한다.
  3. 실시간 제어실행 중 사용된 토큰과 경과 시간을 모니터링하면서, 예산이 남으면 검증을 더 엄격하게 하고, 예산이 부족하면 검증을 건너뛰거나 단계를 축약한다.

3구조적 핵심 예시

"새로운 에이전트가 기존 방법보다 20% 더 정확하다"고 주장하려면, 같은 테스트 데이터에서 같은 난수 시드(randomseed)로 새 방법과 기존 방법을 각각 5번씩 실행했을 때, 새 방법이 일관되게 더 높은 정확도를 보여야 한다. 또한 새 방법이 API를 100번 호출한다면, 기존 방법도 정확히 100번으로 제한해 공정하게 비교한다.

4단계별 동작 과정

  1. 베이스라인 명확화비교할 기존 방법(베이스라인)을 정확히 정의하고, 그 성능을 측정한다. 약한 베이스라인이 아니라 합리적으로 강한 기존 방법을 선택한다.
  2. 난수 시드 통제난수 시드를 고정해 두 방법 모두 같은 난수열을 사용하도록 한다. 이렇게 하면 결과의 변동을 최소화하고 재현 가능성을 보장한다.
  3. 연산 예산 동등화API 호출 횟수, 추론 시간, 생성 토큰 수 등을 새 방법과 기존 방법에서 같게 제한해, 연산량 차이로 인한 성능 차이를 제거한다.

남은 문제: 자기개선의 한계, 안전, 앞으로의 연구 방향

검증 한계·보상 해킹·안전성 등 자기개선 에이전트가 아직 풀지 못한 문제와 향후 연구 방향 정리.

1상대의 출발점 확인

초반에는 에이전트가 스스로 개선될 수 있다는 개념이 매력적으로 보였다. 하지만 실제로 자기개선 에이전트를 구현해 사용하다 보니 세 가지 근본적인 문제가 드러난다. 첫째, 에이전트의 답이 정말 맞는지 검증할 방법이 없을 때가 있다. 둘째, 성능 지표만 높이려고 규칙을 위반하거나 꼼수를 부린다. 셋째, 위험한 행동이나 민감한 정보 노출을 막을 방법이 없다.

2질문 제기

에이전트가 스스로 개선되도록 놔두면, 정말 좋아지는지 어떻게 확인하고, 위험하지 않도록 어떻게 통제할 수 있을까?

3구조적 핵심 예시

검증 한계: 에이전트가 수학 문제에 "정답은 42입니다"라고만 쓰는데, 실제로 맞는지 자동으로 확인할 방법이 없다. 보상 해킹: 성능을 높이려고 문제의 규칙을 어기면서도 점수를 올리는 방법을 학습한다. 안전성: 에이전트가 보안 위험이 있는 코드를 생성하거나 개인정보를 노출시킬 수 있다.

4단계별 동작 과정

  1. 검증 문제 인식모든 답을 자동으로 검증할 수 없다는 근본적 한계를 인식하고, 어떤 영역에서는 인간 평가가 필요하다는 점을 받아들인다.
  2. 보상 해킹 방지성능 지표뿐만 아니라 에이전트의 실제 행동이 규칙을 따르는지 감시하고, 규칙 위반 행동에 페널티를 부여한다.
  3. 안전 기준 수립에이전트가 생성할 수 있는 행동의 범위를 사전에 제한하거나, 위험한 결과가 나올 때 즉시 차단하는 필터를 추가한다.
